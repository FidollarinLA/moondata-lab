# MoonData Lab：交给人工的产品审阅

审阅日期：2026-10-20。对象：本地工作区，v0.3 后续改进。结论对应下列证据，不代表正式赛事评审或用户访谈。

## 我的判断

已经能帮助使用者处理**受支持的扁平表格**：上传、选轴、画图、检查缺失与统计、下载结果，形成完整闭环。当前适合愿意核对字段和统计方法的人试用。尚不足以宣传为“任何数据直接交给 AI 都能正确分析”的通用产品，也还不能据自动化通过率断言普通用户觉得好用。

本次直接检查了桌面截图和 390px 手机截图。两个开始入口使“生成数据”和“处理已有数据”的区别更明确；选轴及统计解释可见，手机号宽度下图中文字保持 12px。页面在有较长结果表时仍较长；对首次使用者，助手与手动绘图两条路径是否造成困惑，需要真人操作观察。

## 已发现并修复

| 问题 | 影响与改动 | 复测证据 |
| --- | --- | --- |
| 上传入口不够突出，首页容易被理解为只能生成模板 | 增加“我已有数据 / 我想生成数据”两个直接入口 | 浏览器实测点击上传入口触发文件选择，导入公开 cars.json 并完成选轴和报告 |
| 字号偏小、次要信息颜色偏淡 | 增大表单、说明与表格字号，调深主要次要文字；本次没有声称完成全部 WCAG 审计 | 桌面及手机截图；页面无横向溢出 |
| 手机把固定 800 宽 SVG 整体缩小，图中文字跟着缩小 | 按真实容器宽度绘图，减少手机刻度，图例换行 | 390px 视口，图宽 360px，渲染文字最小 12px，392 个有效点完整显示 |
| 推荐 flights_airport 图时报超过 1000 分组 | 推荐器优先选择限制内的类别列，避免把高基数 count 作为分组轴 | 真实文件 5366 行通过；另有 300 类别独立回归用例 |
| 柱状图默认均值可能被误读为合计 | 纵轴标签明确写实际的“平均值 / 总和”等；保留用户选择 | Node 回归检查标签与实际聚合一致 |

这次没有把默认聚合改成总和：数量、价格、温度适用方法不同，用户仍须选择。多列共轴也需要确认单位和尺度，目前只提示，不自动猜测或换算。

## 数据和计算证据

- [公开回归完整记录](../artifacts/public-regression.json)：40/40 份不同命名的公开表格通过导入、概览、推荐绘图、报告重算；有数值列时还比较独立均值和直方图总计。
- 来源为 [Vega datasets](https://github.com/vega/vega-datasets)，锁定提交 `175a81ca00b2a0d9bd1159ddcf2b7b232e591d93`。涵盖交通、气候、人口、就业、金融、体育、生物等；去除了 flights 等同源大小变体和生成分布样本。它们由同一个目录整理，**不能称为 40 个独立采集机构或原始业务现场**。每项记录保留上游来源、许可元数据、URL、SHA-256 和行列数；不代替原始许可核查。
- [公开数据浏览器旅程](../artifacts/product-review.json)：cars 原始 406 行，Horsepower 与 Miles_per_Gallon 完整配对 392 行；独立均值 23.44591836734694，MoonBit 结果 23.445918367346934。不是只检查导入成功。
- [桌面截图](../artifacts/product-review-desktop.png)、[手机截图](../artifacts/product-review-mobile.png)；[常规浏览器验收](../artifacts/browser-acceptance.json) 21 项通过，包括坏输入恢复、改变选项禁用旧导出、取消请求、跨格式导入和移动端布局。
- 本轮 `node scripts/check.mjs`：65 项 Node 测试、JS 后端 15 项 MoonBit 测试、Wasm GC 后端 15 项全部通过。浏览器模型协议桩不是实际模型；此前本地 Qwen 的 8 项流程结果也不能外推为这 40 份数据的对话理解准确率。

Vega 的 gallery_examples 包含嵌套 JSON，原先回归被拒绝。它属于当前明确不支持的形状，没有偷偷扁平化后纳入 40 项成功数。现有浏览器负例验证嵌套对象报错且保留原数据。

重跑：先按 README 准备工具链与浏览器依赖；执行 `node scripts/check.mjs`、`node scripts/public-regression.mjs`、`node scripts/product-review.mjs`。公开回归首次需要联网，原始缓存写入忽略的 `.local/public-regression/`，不提交私人上传数据。

## MoonBit 选题是否站得住

按用户提供的选题原则，我认为**方向成立，适合继续做**：任务明确，有可下载、可复算的输出；通用表格探索有成熟需求。可参考 Data Formulator 的交互思路，以及常见数据处理和可视化生态。这里不能声称达到这些成熟工具的能力或兼容其标准。

生态贡献应落在可独立使用的 MoonBit CSV 解析、可复现数据生成、统计、聚合及边界契约，而不仅是一个调用模型的聊天框。本项目已把这些计算放在 MoonBit 并以 JS / Wasm GC 测试；Node 负责会话与工具编排，浏览器负责交互和绘图。Qwen 是接入的预训练模型，llama.cpp 是运行器；离线模板和字段推荐是确定性规则，均不能冒充新训练的模型。

下一阶段值得把计算核心的独立使用示例、模块边界、性能限制和复用说明补齐，便于其他 MoonBit 开发者直接采用。没有赛事完整官方规则，因此不能替主办方承诺通过初审或最终验收。

## 发布前尚未解决

| 优先级 | 限制 | 人工验收或后续行动 |
| --- | --- | --- |
| 高 | 尚无首次使用者测试 | 找几位未见过项目的人，各自完成上传、选轴、修改聚合、导出和解释缺失；记录卡住位置，不先教操作 |
| 高 | 内存会话，刷新及服务重启的行为需要用户理解 | 核对界面提示；数据下载后可重新导入，长期需要显式保存/恢复工作区 |
| 高 | 不支持 XLSX、PDF、图片、任意嵌套 JSON；模型上下文字段有限 | 不宣传“任意数据”；后续按真实需求增加 Excel 与导入映射 |
| 高 | 小模型可能选错字段或误解问句 | 用户核对坐标与工具参数；增加含歧义、宽表、追问和拒答的真实对话评测 |
| 中 | 共轴量纲、日期原始顺序连接、抽样与前 50 类别可能造成误读 | 保留方法提示并安排人工解释测试；必要时增加排序、分面或更明确的截断反馈 |
| 中 | 回归主要来自整理好的单一目录 | 补充不同机构的原始 CSV、编码、日期和脏数据；现有通过率不覆盖这些情况 |
| 待完成 | GitHub 未登录，尚未推送；白底轻动画展示、流程与架构图未完成 | 官方设备登录需用户完成；README 内只放支持的图形，交互动画放独立 HTML |
