# AI 使用说明（可解释性）

赛事允许 AI 辅助编码、测试与文档，但参赛者必须能解释技术选择并对质量负责。本文件记录本项目的分工，便于评审与作者自检。

## 目标（人定）

- 用 MoonBit 实现可独立测试的表格解析、合成生成与描述统计契约。
- 用本机 Node + 中文 UI 编排会话、导入导出与可选模型工具循环。
- 明确边界：不冒充任意数据平台；报告数值必须来自 MoonBit 重算。

## AI 可辅助的部分

- 样板代码、测试用例草稿、中文 UI 文案与文档初稿。
- 回归脚本、CI 配置、错误信息润色。
- 本地小模型（Qwen）仅作**图表配置规划**：输出 JSON 方案，由同一套字段校验与 MoonBit 计算执行。

## 必须由人掌握 / 仓库写死的红线

| 红线 | 原因 |
| --- | --- |
| 数值核心在 MoonBit，JS 不静默改算 | 验收「MoonBit 为主」与结果可复核 |
| Agent 无 shell / 任意代码 / 任意网络工具；成功调用在 `trace[].contract` / `evidence.toolAllowlistValidator` 留下 MoonBit 白名单证据（非模型自述） | 安全与可解释边界 |
| 报告忽略客户端伪造的 statistics | 防模型或前端编造数值 |
| 合成数据带 `_synthetic`；导入真实性不背书 | 诚实产品定位 |
| 总体标准差 vs 样本标准差分开暴露 | 统计语义不被 UI 糊弄 |

## 作者应能口头解释的三点

1. 为什么 Park–Miller + Schrage 而不是 `Math.random`（可复现、跨 JS/Wasm 一致）。
2. 为什么缺失不补零、相关常数列返回 null（契约见 METHODS）。
3. 为什么模型只看到字段元数据与精简工具结果，看不到原始行采样点。

若以上三点说不清，则本期交付不算「作者掌握」。
